## 기존 근거와 새로운 측정

대기 합성 ROI의 Near75 대표거리 평균3.4359km, 깊이 표준편차 평균 .1958km.
Alpha 범위 .11035–.67041이며 작은 ROI의64행 양쪽128경계 모두 완전한10–90% 전이를 담지 못했다.
따라서 이전 ROI로 경계 폭을 확정할 수 없다. 동일 후보 촬영의 Near752배 Composite alpha를
화면 전체 폭1920×64 CSV로 추가 저장한다. 새 밀도/해상도/스텝 후보나 대량 이동 캡처는 없다.

분석기는 각 행의 alpha 최고점에서 좌우로 나가며 .9/.1배의 첫 교차를 찾는다.
두 문턱이 모두 있으면 픽셀 폭을 기록하고, 없으면 censored로 남긴다. 0이나 추정값으로 채우지 않는다.
여러 구름이 겹친 광선의 영상상 전이이며 단조인 입체 표면 두께나 월드 수직 두께와 같지 않다.

보존 계보는 `notes/capture-archive/2026-09-21/build-captures/cloud-near-far/42308-45389781/rays.csv`.
25m 두 근경 광선의 Base양수 표본122/99개 중 최종0이 된 비율61.48%/71.72%,
최종/Base 밀도 적분량은31.08%/6.59%였다. 과거 코드/입력이므로 현재 전체 구름에 그대로 일반화하지 않는다.

## 코드에서 확인한 경계 의미

`Noise.hlsli`의 침식 가중치는 `1−smoothstep(.45,.90,baseDensity)`다.
baseDensity는 공간상 표면 거리가 아니라 높이와 Weather 등이 곱해진 값이다.
계보의 최대Base .467/.412는 이 문턱의 시작 부근 또는 아래여서 몸체도 거의 최대 침식을 받을 수 있다.
`DetailCoreForComparison`은 remap/profile/Weather로 코어를 근사하고 F1 보호값이 이를 완화한다.
현재 저장 Cumulus JSON에 보호 필드는 없어 기본0이다. 사용자가 별도 미저장 UI값을 썼는지는 캡처로 추정하지 않는다.

높이 profile의 하단fade .233은 설정 두께2000–3200m에서466–746m, 상단fade .496은992–1587m다.
하부 밀도 .406→상부1 전환도 겹친다. 이것만으로 높이를 주원인으로 단정하지 않으며,
이전 사용자 높이profile 변경 생략 지시와 전이폭 제거 선택을 유지한다.

## 다음 수정 판단

넓은 경계는 대기2배 채택만으로 해결되지 않는다. Cloud T 자체는 대기 배율과 독립이다.
공간상 코어와 낮은밀도 외곽을 혼동하는 침식 가중치가 우선 조사 대상이며, 코어 보호를 높이는 것과
윤곽/내부명암 개선을 구분한다. 현재 근거만으로 새 밀도 기본값을 채택하지 않는다.
다음 구조 후보 전에는 같은 경계의 광선 띠에서 Base→높이→침식 손실을 비교해 위치를 확인해야 한다.
이미 끝낸 해상도/View step/Base대비/전이폭 후보는 반복하지 않는다.
