# Stage 15 — 시선 표본 지터로 동심원 줄무늬 제거 (2026-09-25)

## 문제

포트폴리오 영상 촬영 중 **Stratus 타입의 F7(태양 쪽 전경)·F8(구름층 위) 시점**에서
카메라를 중심으로 한 **동심원 모양의 밝고 어두운 줄무늬**가 구름 위에 보였다.

- 구름층을 위에서 비스듬히 내려다볼 때 가장 뚜렷했다. 얇고 넓은 Stratus가 특히 심했다.
- 줄무늬는 구름을 따라 움직이지 않았다. 카메라에 붙어 있어서, 구름이 흘러가도 원이 제자리에 남았다.
- 화면 가까운 쪽(아래쪽)일수록 원의 간격이 넓고, 멀어질수록 촘촘했다.

## 원인

시선 레이마칭(`RaymarchCloud`)은 레이를 거리 `step`(기본 100m, 24~50km에서 최대 125m)
단위 구간으로 나누고, **각 구간의 정확히 가운데(`cursor + 0.5 × marchLength`) 한 점**에서
밀도를 읽어 그 구간 전체를 대표하게 했다.

모든 픽셀이 같은 규칙을 쓰므로, 카메라에서 **같은 거리에 있는 표본끼리 정확히 같은 줄**에 선다.
구름층의 밑면·윗면처럼 밀도가 높이에 따라 급하게 바뀌는 곳을 레이가 비스듬히 지나면,
어떤 거리 구간은 표본이 경계 안쪽에, 다음 구간은 바깥쪽에 떨어진다. 이 "안쪽/바깥쪽"이
카메라 기준 거리마다 번갈아 나타나므로, 화면에는 카메라를 중심으로 한 **동심원 줄무늬**
(샘플링 에일리어싱, banding)로 보인다.

Stratus는 두께가 850m로 얇고 밑면 fade가 거의 없어 밀도 경계가 급하다. 그래서 한두 표본의
차이가 곧바로 밝기 차이가 되어 줄무늬가 가장 잘 드러났다.

## 해결 — 픽셀마다 구간 안 표본 위치를 흩는다 (interleaved gradient noise 지터)

핵심 아이디어: **표본이 구간 안 어디에 있든 그 구간을 대표한다는 사실은 같으므로,
"가운데"라는 고정 위치 대신 픽셀마다 다른 위치에서 읽게 해서 줄을 깨뜨린다.**

```hlsl
// main: 픽셀마다 0~1 값을 하나 정한다.
viewSampleJitter = InterleavedGradientNoise(input.position.xy);

// RaymarchCloud: 구간 가운데(0.5) 대신 지터 위치에서 밀도를 읽는다.
float sampleDistance = cursor + viewSampleJitter * marchLength;

float InterleavedGradientNoise(float2 pixel)
{
    return frac(52.9829189 * frac(dot(pixel, float2(0.06711056, 0.00583715))));
}
```

왜 이렇게 하면 해결되나:

1. **줄의 원인을 직접 없앤다.** 줄무늬는 "모든 픽셀이 같은 거리에서 읽는다"는 정렬에서 생긴다.
   이웃 픽셀이 구간 안 서로 다른 위치(0~1)에서 읽으면 같은 거리에 표본이 정렬되지 않으므로
   경계 안/밖이 거리마다 한꺼번에 바뀌는 현상이 사라진다.
2. **구조적인 무늬를 눈에 띄지 않는 미세한 노이즈로 바꾼다.** 에일리어싱 오차 자체는 남지만,
   화면 전체에 넓게 이어진 원 대신 픽셀 단위의 고르게 퍼진 오차가 된다. 사람 눈은 큰 규칙적
   무늬에 민감하고 고주파 노이즈에는 둔감하다.
3. **Interleaved gradient noise를 고른 이유.** 완전 랜덤(해시)은 뭉친 곳과 빈 곳이 생겨 얼룩처럼
   보인다. IGN은 이웃 픽셀끼리 값이 고르게 흩어지도록 설계된 저불일치 패턴이라 같은 표본 수로
   더 고른 노이즈가 된다. 텍스처나 추가 리소스 없이 셰이더 한 줄로 계산된다.
4. **적분 범위는 바뀌지 않는다.** 구간 경계(`cursor`, `marchLength`), Beer–Lambert `exp(-ρσΔs)`,
   step 수, coarse 탐색·되감기, early exit는 모두 그대로다. 바뀐 것은 "구간 안 어디서 읽는가"뿐이라
   평균 밝기와 성능은 유지된다.
5. **시간 흔들림이 없다.** 지터는 화면 픽셀 좌표로만 정하고 시간에 따라 바꾸지 않는다. 이 프로젝트는
   TAA(시간 누적)를 쓰지 않으므로, 매 프레임 바뀌는 지터는 오히려 깜빡임이 된다. 고정 패턴이라
   정지 화면·영상 모두 안정적이고 결정성(같은 입력 → 같은 출력)도 유지된다.

## 변경 파일

- `shaders/VolumetricClouds.hlsl`
  - `static float viewSampleJitter`와 `InterleavedGradientNoise()` 추가
  - `main`에서 `input.position.xy`로 픽셀별 지터 설정
  - `RaymarchCloud`의 정상 표본 위치를 `cursor + viewSampleJitter * marchLength`로 변경
- 영향 없는 경로: 태양 광선(`ComputeLightTransmittance`), Deep Shadow 캐시, 구간 중점 진단 표본(숫자 9 등),
  디버그 93~95 점유 적분, NoiseLab 미리보기는 기존 계산을 그대로 쓴다.
- CPU 기준 수학(`Stage9OptimizationMath.h`), High 상수, cbuffer 레이아웃은 바뀌지 않는다.

한계:

- 에일리어싱 오차를 없앤 것이 아니라 흩은 것이다. 극단적으로 확대하면 픽셀 단위 미세 노이즈가 보일 수 있다.
- 표본 수를 늘리는 해결(step 축소)은 비용이 선형으로 늘어 채택하지 않았다. 지터는 비용이 거의 0이다.
- 시간 누적(TAA)을 도입하면 지터를 프레임마다 바꿔 노이즈까지 수렴시키는 방식으로 확장할 수 있다.

화면 승인: 사용자가 포트폴리오 영상(Stratus F7·F8 재촬영 컷)에서 확인한다.
