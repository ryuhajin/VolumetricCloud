# feature/pre-rebuild-archive 변경 기록

## 1. 목표와 배경

- 단계별 재구축을 시작하기 전에 현재 볼류메트릭 클라우드 구현과 생성 캐시를 복구 가능한 원격 브랜치에 보존한다.
- 이 브랜치는 `main`에 병합하지 않으며, 이후 구현의 비교 자료와 코드 참조 용도로만 사용한다.

## 2. 기존 구현과 관찰된 문제

- 평면 구름층, weather/placement map, base/detail 3D noise, 조명, temporal reconstruction, 영구 캐시와 디버그 UI가 하나의 렌더 경로에 함께 결합되어 있다.
- 최종 렌더 결과가 목표 품질에 도달하지 않았고 형태, 조명, temporal, 캐시 경로를 동시에 디버깅해야 해 원인 격리가 어렵다.

## 3. 원인 분석과 근거

- 현재 `Renderer`가 구름 리소스 생성, 캐시, raymarch, temporal, 합성, 계측과 UI 연결을 함께 담당한다.
- 밀도, 배치, 조명과 재구성 단계가 동시에 활성화되어 단일 기능의 시각적 완료 조건을 독립적으로 확인하기 어렵다.

## 4. 검토한 대안

- 현재 구현을 `main`에 병합하는 안은 안정 브랜치 규칙과 맞지 않아 선택하지 않았다.
- 별도 저장소를 만드는 안은 기존 커밋과 문서의 추적성을 잃으므로 선택하지 않았다.
- 현재 상태를 별도 보존 브랜치에 고정하고 `main`에서 재구축하는 안을 선택했다.

## 5. 선택한 해결 방법

- 현재 작업 트리의 소스, 문서와 캐시를 이 브랜치에 체크포인트로 커밋하고 원격에 푸시한다.
- AI 에이전트 전용 단계별 계획 PDF는 로컬에만 유지하도록 `.gitignore`에서 제외한다.

## 6. 실제 수정 내용

- 이 문서는 보존 브랜치의 목적과 검증 상태를 기록한다.
- 보존 대상 구현 자체는 재설계하거나 정리하지 않는다.

## 7. 캐시·호환성·성능 영향

- 현재 생성된 base/detail/weather/placement 캐시와 `.cso`를 그대로 보존한다.
- 재구축 브랜치는 이 캐시와 사용자 프리셋을 호환 대상으로 삼지 않는다.

## 8. 테스트 및 실행 결과

- Debug 빌드: 성공 (`cmake --build build --config Debug`)
- Release 빌드: 성공 (`cmake --build build --config Release`)
- Release ctest: 2/2 성공 (`VolumetricCloud.CacheSmoke`, `VolumetricCloud.CodeTests`)
- 시각 품질: 재구축 결정에 따라 승인 대상이 아님

## 9. 남은 문제와 후속 개선

- 실제 개선은 `feature/rebuild-foundation`에서 단계 0부터 진행한다.
- 이 브랜치에는 보존 이후 기능 변경을 추가하지 않는다.
