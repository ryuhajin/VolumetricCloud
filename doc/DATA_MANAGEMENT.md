# 테스트 산출물과 프로젝트 용량 관리

일반 배포와 로컬 검사 패키지를 [분리](BUILDING.md)했다. 아래 tests/tools 및 정리 도구는 로컬 개발용이며
공개 배포에 포함하지 않는다. 일반 원격 코드는 테스트 폴더 없이 빌드된다.

## 보관 기준

소스, 기본 기능 테스트, 셰이더, 원본 `presets/` 8개, 의존성, 문서, 개인 노트와 Git 이력은 보존한다.
현재 `build/` 하나에서 Debug/Release를 사용한다. 실행 파일·디버그 심볼·증분 빌드 파일은 유지하며
별도 진단/strict 빌드는 필요한 동안만 보관한다. IDE 설정과 `captures/noise-lab` 개인 설정·백업은 캐시가 아니다.

테스트 출력은 검증 중인 임시 자료다. **테스트 → 분석 → 필요한 사용자 화면 승인 → 프로젝트 반영 →
반영 후 검증 → 노트 기록 → 산출물 삭제** 순서로 처리한다. 기각하거나 종료한 실험도 결론 기록 후 삭제한다.
실패 조사 중·사용자 비교 대기 자료와 재분석 입력은 보존한다. 자동 테스트 PASS는 화면 승인을 대신하지 않는다.
이 규칙은 과거 문서의 영구 캡처/불변 baseline 보존 지시보다 우선한다. 보관 중인 baseline을 덮어쓰지는 않는다.

## 기록과 진행 중 자료

- 노트에 날짜, 실행 명령·환경·카메라·설정, 채택 값, 주요 수치·오차·성능, 채택/기각 이유,
  승인 근거, 한계, 삭제 경로·날짜·확보 용량을 적는다. 기록을 확인한 뒤 원본 산출물을 삭제한다.
- 대용량 PNG/HDR/CSV/캐시를 `notes/`로 이동하거나 압축해서 쌓지 않는다. 상세 작업 기록은 노트에만 추가한다.
  공식 문서는 현재 구현·인터페이스·재현 명령을 갱신하고, 기존 수치/승인 이력은 지우지 않는다.
- 진행 중 자료는 `tools/ArtifactRetention.json`의 보호 목록에 등록한다. 현재는 최신 Release fBm 비교,
  근경 경계 분석의 대기 입력과 분석 결과·기존 노트 수치 계보를 보관한다. 연결된 입력을 함께 보호한다.
- 완료 후 노트에 결론을 남기고 보호 목록에서 해제한 다음 정확한 실행 폴더만 삭제한다.
  나이·수정일·용량 또는 자동 PASS만으로 시각적 비교 자료를 삭제하지 않는다.
- 삭제한 경로는 역사적 식별자다. 예전 문서에 경로가 있어도 파일이 존재한다고 간주하지 않는다.

## 정리 도구

`tools/CleanArtifacts.ps1`은 계획 파일의 대상만 검사한다. 기본은 미리보기이며 `-Apply`가 있어야 삭제한다.
프로젝트 루트에서 다음 형태의 **로컬** 계획 파일을 만든다. `note`는 기존 Markdown 노트이며 모든 대상의
정확한 상대 경로와 결과/삭제 근거가 먼저 기록되어 있어야 한다. 아래 ID는 설명용이다.

```json
{
  "version": 1,
  "note": "notes/해당-작업.md",
  "targets": [
    {"path": "build/captures/cloud-detail-spectrum/완료한-실행ID", "reason": "채택 반영과 검증 완료, 노트 기록 완료"},
    {"path": "build/Release/shader-cache", "reason": "재생성 가능한 컴파일 캐시 정리"}
  ]
}
```

```powershell
pwsh -NoProfile -File tools/CleanArtifacts.ps1 -Plan notes/cleanup-plan.json
pwsh -NoProfile -File tools/CleanArtifacts.ps1 -Plan notes/cleanup-plan.json -Apply
```

실행·빌드·테스트가 끝난 뒤 정리한다. 도구는 전체 계획을 먼저 검증하며 보호 목록·Git 추적 파일·프로젝트 밖
경로·junction/symlink·중복 대상은 거부한다. 현재 build 전체 삭제는 허용하지 않는다. 잠긴 파일과 읽기 전용
파일은 강제 삭제하지 않고 BLOCKED로 보고한다. REMOVED/ABSENT/BLOCKED와 대상 용량은 지정 노트에 기록된다.
BLOCKED가 있으면 일부 대상만 정리되었을 수 있으므로 경고와 실제 잔여 용량을 확인한다.
새 산출물 종류가 생기면 무제한 경로를 허용하는 대신 도구의 허용 목록과 보호/회귀 검사를 함께 갱신한다.

## 반복 테스트의 출력

- 기본 CTest는 `VCLOUD_ENABLE_DIAGNOSTIC_TESTS=OFF`를 유지한다. 대량 비교는 필요한 진단만 명시적으로 실행한다.
- `DetailCoreSliderSmoke`(2026-09-24 슬라이더와 함께 폐기, 과거 기록): 모든 수치·복원·프리셋·D3D 검사를 마친 뒤 이번 실행의 HDR을 제거하고
  `captures/detail-core-slider/latest-success.txt` 하나에 결과·동등성·reload 수치를 갱신한다.
  상대 `captures/` 위치는 실행 작업 디렉터리에 따른다. 실패·중단한 실행 폴더는 보존한다.
- `RunDeterminism.ps1`: 성공한 행렬의 로그를 WorkRoot의 `latest-success.log` 하나로 갱신하고
  이번 실행의 셰이더 복사본·캐시·덤프를 삭제한다. 실패·중단 시 실행 폴더 전체를 보존한다.
- 성공 요약은 다음 실행에서 교체된다. 작업 결론에 필요한 수치는 작업 종료 전에 노트에 기록한다.
- 정리 작업의 검증 때문에 완료된 대량 비교를 다시 촬영하지 않는다. 빌드/기본 회귀에서 생긴
  재생성 캐시도 작업 종료 시 같은 절차로 정리한다.
